Root cause to investigate:
The mobile navigation is positioned relative to the viewport, while the cards are inside one or more nested containers with additional horizontal padding or margins.

Do not guess new left/right pixel values.

====================================================
PHONE-ONLY REQUIREMENT
====================================================

Apply this fix only for widths up to 820px.

The exact left and right edges of .mobile-nav must match the actual rendered left and right edges of the primary content cards.

Use the first visible main card or the main card column as the geometry source.

Preferred implementation:

1. Identify the shared card wrapper or actual card selector, such as:
- .main
- .mission-grid
- .context-banner
- .panel
- another current content wrapper

2. Create one shared phone content-width wrapper rule.

For example:

.main {
  width: 100%;
}

.main > .context-banner,
.main > .panel,
.main > .mission-grid,
.main > .workspace,
.main > section {
  /* preserve current layout */
}

.mobile-nav {
  left: 0;
  right: 0;
  width: auto;
}

But place .mobile-nav inside or align it to the same containing block as the cards.

Best solution:
- move .mobile-nav into the same .main container if this does not break fixed positioning;
OR
- set a shared CSS custom property from the exact total card gutter;
OR
- use a centered width equal to the card column:

.mobile-nav {
  left: 50%;
  right: auto;
  width: calc(100% - (2 * var(--actual-phone-card-gutter)));
  transform: translateX(-50%);
}

The value of --actual-phone-card-gutter must equal the final rendered distance from the viewport edge to the card edge, including all nested padding and margins.
