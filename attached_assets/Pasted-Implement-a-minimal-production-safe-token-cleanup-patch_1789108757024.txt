Automatic token deletion rules

A token must be completely removed from the operational system when either condition is met:

1. Price has dropped by 80% or more from the token’s tracked reference/high price:
    priceDropPercent >= 80

OR

2. The token is older than 30 minutes AND its score is below 40:
    tokenAge > 30 minutes && score < 40

Use strict thresholds:

* Score 40 must NOT be deleted by rule #2.
* Age exactly 30 minutes must NOT be deleted by rule #2.
* Price drop exactly 80% MUST be deleted.

Important implementation requirements

Create one centralized cleanup function/predicate, for example:

shouldDeleteToken(token)

It should return true when:

priceDropPercent >= 80 || (score < 40 && tokenAgeMs > 30 * 60 * 1000)

Run this cleanup automatically wherever tokens are refreshed/updated so that stale tokens do not remain in the system.

When a token qualifies for deletion:

* remove it from the active token collection;
* remove it from persistent token storage/database;
* remove it from token caches;
* remove it from monitoring/watch/probe queues if applicable;
* remove it from API/dashboard operational state;
* prevent it from being re-added by stale cached data;
* make the deletion idempotent and safe if the token is already absent.

Do NOT delete unrelated system data.

If the project keeps trading/order/history/audit records separately, preserve those records unless they are explicitly part of the operational token entity. Do not destroy financial history just because the token is removed from the active token registry.
